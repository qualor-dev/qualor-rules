# Backlog

The ordered queue of rules to write. `/write-rules [N] [language]` takes the first N `todo` rows
from the top (of that language, if one is named), and nothing else. Read `COVERAGE.md` to add rows
and `.claude/skills/write-rules/SKILL.md` for the procedure.

- **id**: the rule id, `<lang>.<name>` (the rule is `rules/<lang>/<category>/<name>.yml`). An id
  `<lang>.<name>#<topic>` is a maintenance item on an existing rule: a documented limit to record,
  a framework to add, a false-positive shape to fix.
- **kind**: `issue` for taint data flow and definite misuse, `hotspot` for "review this usage"
  where context decides (ruling M1 of 6A; see COVERAGE.md "Kind and severity").
- **status**: `todo` → `in-progress` (a run took it) → `done` (merged into `main`) or `blocked`
  (the notes end with the question for the maintainer). A rule file exists exactly while its row
  is `in-progress` or `done`; `npm run check` enforces it.
- **notes**: what the rule must cover beyond the obvious, safe shapes for `ok:` lines, and hints
  where to look in the official docs. Hints are not facts: confirm each one in the docs.
- Only the run's controller edits this file (on `main`); implementers never do. Each rule commit
  carries `Backlog: <id>` in its body, so an interrupted run can be resumed.
- Order: maintenance items first, then the spec §7 categories (design spec, first scope), then rows
  chosen by COVERAGE.md's priority rules. New rows go below the last `todo` row unless COVERAGE.md
  says a row outranks it.
